# Словарь данных итоговой панели

Итоговый артефакт — файл `monthly_panel.csv`, содержащий ровно одну строку на
пару «инструмент — календарный месяц». Дубликаты по этой паре запрещены и
проверяются программно. Панель сопровождается файлом `dataset_manifest.json`.

## Схема панели

| Поле | Тип | Единица | Правило формирования |
|---|---|---|---|
| `secid` | строка | — | Код инструмента в терминах источника |
| `month` | дата | — | Первый день календарного месяца наблюдения |
| `price_date` | дата | — | Дата последней допустимой цены закрытия месяца |
| `month_end_price` | число | рубли | Цена закрытия на `price_date` |
| `return_1m` | число | доля | Цена месяца `t` к цене `t−1` минус единица |
| `momentum_prev_3m` | число | доля | Цена месяца `t−1` к цене `t−4` минус единица |
| `volatility_3m` | число | — | Стандартное отклонение дневных доходностей за три календарных месяца |
| `key_rate_pct` | число | % годовых | Действующая ключевая ставка на последний торговый день месяца |
| `key_rate_change_pp` | число | п.п. | Разность действующих значений на конец смежных месяцев |
| `target_return_next_1m` | число | доля | Цена месяца `t+1` к цене месяца `t` минус единица |
| `quality_flags` | строка | — | Перечень пометок через точку с запятой; пусто, если замечаний нет |

## Правила

* **Дубликаты** по паре «инструмент — месяц» запрещены.
* **Пропуски** в числовых полях допустимы только при непустом значении
  `quality_flags`, указывающем причину.
* **Целевая переменная** последнего месяца периода наблюдения остаётся пустой,
  поскольку следующий месяц ещё не наблюдён; такие строки не считаются
  оценёнными прогнозами.
* **Первый месяц с полным набором признаков** (`s₀`) определяется по всем пяти
  признакам (связывающее ограничение — моментум); первые месяцы ряда, где
  моментум и волатильность недоступны, помечаются в `quality_flags`, а не
  рассчитываются по неполному окну.

## Файл манифеста `dataset_manifest.json`

Манифест фиксирует происхождение панели и содержит:

* версию протокола;
* период наблюдения;
* список инструментов;
* перечень использованных исходных файлов с их контрольными суммами;
* версию кода и версию зависимостей;
* дату построения;
* перечень применённых к ряду корректировок (`adjustments`): `secid`, `date`,
  `event_type`, `coef`, `source` (например, приведение цен к единому масштабу
  по сплиту — шаг A3).

Манифест должен позволять восстановить, из каких именно исходных файлов
получена панель, вплоть до контрольных сумм каждого файла.

## Справочники и промежуточные таблицы

Помимо итоговой панели, конвейер создаёт несколько промежуточных файлов.
Их схема фиксируется здесь, чтобы анализ был воспроизводим.

### Замок состава выборки — `configs/universe.lock.toml`

Файл-замок вычисляется `universe` (этап 4) и фиксирует состав выборки.
Все последующие этапы читают только его и не выполняют отбор повторно.
Изменение замка = изменение состава выборки и требует записи в журнале
решений. Замок не перезаписывается автоматически: при существующем файле
команда `universe` завершается ошибкой, если не передано явное
подтверждение `--force`.

| Поле | Тип | Смысл |
|---|---|---|
| `version` | строка | версия протокола (правило отбора) |
| `selection_board` | строка | биржевой режим торгов |
| `selection_year` | целое | базовый год отбора по обороту |
| `formation_date` | дата | дата формирования состава |
| `secids` | массив | коды отобранных инструментов |
| `exclusions_file` | строка | имя файла исключений |
| `secid` (под `[[instruments]]`) | строка | код выбранного инструмента |
| `turnover` (под `[[instruments]]`) | число | оборот инструмента за базовый год |

### Файл исключений — `configs/universe_exclusions.csv`

Фиксирует причины недобора выборки. Колонки: `secid, reason, turnover, rank`.

Сюда же вносится результат ручной проверки (`review`, этап 4): после
построения состава человек проверяет список; исключение допускается **только**
по причинам качества данных. Недопустимые основания (связанные с ожидаемой
доходностью или «непривычностью» эмитента) отклоняются кодом.

Допустимые причины ручного исключения (`ALLOWED_MANUAL_REASONS`):

| Причина | Смысл |
|---|---|
| `data_gap_unexplained` | разрыв истории без корпоративного события |
| `code_change_unconfirmed` | смена кода/режима без подтверждённой непрерывности |
| `mostly_no_trading` | отсутствие торгов большую часть периода |
| `security_type_mismatch` | расхождение справочных данных о типе инструмента |

### Дневные цены — `data/interim/daily_prices.csv`

| Поле | Тип | Единица | Смысл |
|---|---|---|---|
| `secid` | строка | — | код инструмента |

| `close` | число | рубли | цена закрытия |

Нормализация: фильтр по режиму торгов, приведение дат и чисел, удаление

### Ключевая ставка — `data/interim/key_rate.csv`

| Поле | Тип | Единица | Смысл |
|---|---|---|---|
| `date` | дата | — | дата установки значения |
| `rate` | число | % годовых | действующее значение ключевой ставки |

### Корпоративные события — `data/interim/corporate_actions.csv`

Обязательный вход (его отсутствие — ошибка). Пустая таблица допустима.

| Поле | Тип | Смысл |
|---|---|---|
| `secid` | строка | код инструмента |
| `date` | дата | дата события |
| `event_type` | строка | тип действия (например, `split`) |
| `coef` | число | коэффициент приведения (для сплита/консолидации) |
| `source` | строка | происхождение сведения |
| `retrieved_at` | дата | дата получения |

### Диагностика — `data/reports/`

* `findings.csv` — замечания качества: `secid, date, type, value`;
* `corporate_events.csv` — события корпоративных действий;
* `quality_summary.csv` — сводка по качеству данных;
* `acceptance_report.md` / `.json` — отчёт приёмки этапа 8.

Флаги качества (`quality_flags` в панели) — перечень пометок через точку с
запятой. Возможные значения: `no_trading_days_in_month`,
`missing_close_price`, `stale_price_too_far_from_month_end`,
`no_previous_price` и др. Непустой флаг объясняет пропуск в соответствующем
числовом поле.

## Отчёт оценки модели — `data/reports/model_evaluation.json`

Формируется модельным слоем (команда `evaluate`) поверх готовой панели.
Содержит:

| Поле | Смысл |
|---|---|
| `feature_columns` | перечень признаков, использованных в полном наборе |
| `evaluation.forecast_count` | число спрогнозированных целевых месяцев |
| `evaluation.mse` | средняя квадратическая ошибка (агрегация `securities_then_months`) |
| `evaluation.mae` | средняя абсолютная ошибка |
| `factor_usefulness.<фактор>.usefulness_pct` | прирост ошибки (в %) при удалении фактора |
| `factor_usefulness.<фактор>.direction` | `useful` / `harmful` / `neutral` |

**Правило чтения.** `usefulness_pct > 0` (удалили фактор — ошибка выросла)
означает, что фактор полезен вне выборки; `< 0` — вреден; близко к нулю —
нейтрален. Полезность оценивается только вне выборки, поэтому полезный слой
факторов не должен совпадать с набором, оптимизированным в обучении.

## Отчёт отбора состава — `data/reports/selection_report.json`

Формируется командой `selection` (методика, разделы 3.2–3.4). Содержит:

| Поле | Смысл |
|---|---|
| `model_a.mse` / `.mae` / `.forecast_count` | точность исторического среднего |
| `model_b.mse` / `.mae` / `.forecast_count` | точность OLS с полным набором |
| `model_c.mse` / `.mae` / `.forecast_count` | точность OLS с обновляемым составом |
| `comparison_ba` | разность средних квадратических ошибок (C−B) на периоде оценки |
| `comparison_ca` | разность (C−A) |
| `comparison_ba_win_rate` | доля месяцев, где C точнее B |
| `rebalance_history` | история выбора состава: `rebalance_date`, `selected_groups` |
| `monthly_difference` | ряд месячных разностей MSE (C−B) для бутстрэпа |

**Модели.** A — историческое среднее; B — OLS по каждой акции с полным
набором из пяти признаков; C — OLS по каждой акции, состав пересматривается
раз в квартал по ошибкам предшествующих прогнозов.

## Отчёт бутстрэпа — `data/reports/bootstrap_report.json`

Формируется командой `bootstrap` (методика, раздел 3.5) по отчёту отбора.
Содержит:

| Поле | Смысл |
|---|---|
| `point_estimate` | точечная оценка средней разности MSE (C−B) |
| `lower` / `upper` | границы доверительного интервала |
| `mean` | среднее по псевдовыборкам |
| `replicates` | число повторов |
| `block_months` | длина блока |
| `confidence` | доверительный уровень |
| `seed` | зерно генератора |
| `n_observations` | длина исходного ряда |

## Отчёт устойчивости — `data/reports/sensitivity_report.json`

Формируется командой `sensitivity` (методика, раздел 4.3). Список записей,
каждая — альтернативная спецификация:

| Поле | Смысл |
|---|---|
| `specification` | название спецификации (окно, период отбора, блок, исключение) |
| `comparison_ba` | средняя разность MSE (C−B) |
| `lower` / `upper` | границы доверительного интервала |
| `ci_contains_zero` | содержит ли интервал ноль |
| `n_observations` | длина ряда разностей |
| `detail` | доп. сведения (тип исключения/бумага) |

## Сводный отчёт — `data/reports/summary_report.md`

Формируется командой `report` (методика, разделы 4.1–4.2). Markdown-файл с
таблицей сводных метрик моделей A/B/C, средней разностью MSE (C−B) с
интервалом, сопоставлением с историческим средним, долей месяцев, где модель
точнее, и историей пересмотров. Сопровождается графиками:

* `errors_B_C.png` — месячная MSE моделей B и C на периоде оценки;
* `rebalance_history.png` — число признаков выбранного состава по датам
  пересмотра;
* `bootstrap_distribution.png` — распределение бутстрэп-средних разности C−B.
